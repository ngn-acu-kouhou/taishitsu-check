# 体験会アンケート（啓蒙型Webフォーム）

体験会の参加者に、体験直後にスマホで答えてもらうアンケートです。
満足度を測るだけでなく、**回答後の完了ページで「鍼灸で何が相談できるか」を持ち帰ってもらう**ことを目的にしています。

体験メニューは「鍼灸体験（鍼を1本刺してみる）」と「鍼灸施術（20分程度）」の2種類を想定しています（マッサージは扱いません）。

公開URL（GitHub Pages）: `https://ngn-acu-kouhou.github.io/taishitsu-check/survey/`

## なぜこの設計か（前回の報告書との対応）

「医療介護のつどい 鍼灸マッサージ体験ブース 実施報告書」で挙がった課題を、そのまま設問に落としています。

| 報告書で判明した課題 | このアンケートでの対応 |
| --- | --- |
| 鍼灸でできることの認知不足（12名） | **STEP 5** で18項目から「相談できそうなもの」を選んでもらい、**送信後の完了ページで18項目すべてを解説付きで提示**。設問中は採点も種明かしもせず、読みものとしてゆっくり見てもらう |
| 保険適用や手続きのわかりにくさ（9名） | 完了ページで保険対象6疾患を正式名称つきで明示（同意書の流れを含む）。さらに STEP 6 で保険の認知度を測定 |
| どこに相談すべきか分からない（5名） | STEP 6 で相談先の認知を測定し、完了ページから中信鍼灸師会の会員院一覧へ導線 |
| 「痛そう・怖そう」の心理的障壁 | STEP 4 で体験前の印象（複数選択＋自由記述）と体験後の変化を聞き、**ハードルが下がった度合いを数値で残す**（広報の実績になる） |
| 満足度の選択肢の並びによる誤入力（不満2名は押し間違いの疑い） | 満足度は **「とても満足」を先頭（左端）** に配置。5段階を横並びで表示 |
| 連携マニュアル／1枚広報紙の必要性 | STEP 8 の意向に「適応と保険手続きをまとめた資料がほしい」を入れ、**作る前に需要を確認できる** |
| 広告規制で伝えられる情報が限られる | **STEP 7** であはき法の広告可能8項目を提示したうえで、「ほかに何が分かれば行きやすいか」を選択肢＋自由記述で聞く。**規制の枠内で何を補えばよいか**（体験会での配布物、会員院への助言、会のサイトでの発信）の手がかりになる |

## 設置ずみの構成（2026-09-16 時点）

回答の集計先はすでに構築・動作確認ずみです。**追加の設定作業は不要**です。

| 役割 | 実体 | 置き場所 |
| --- | --- | --- |
| 回答の保存先 | スプレッドシート **鍼灸体験会アンケート回答**（シート名「回答」） | 中信鍼灸師会 `t.shinnkyuu@gmail.com` のドライブ |
| 受け取り口 | Apps Script プロジェクト **鍼灸体験会アンケート受け取り**（`gas/Code.gs` と同じ内容） | 同アカウント |
| 送信先URL | `survey.js` の `CONFIG.endpoint`（`.../exec`） | このリポジトリ |

デプロイ設定は「次のユーザーとして実行：自分（t.shinnkyuu@gmail.com）／アクセスできるユーザー：全員」。
スマホから送信するためにアクセスは「全員」が必要です。合言葉などの認証は付けていないため、
**URLを知られると第三者が偽の回答を送信できます**。会期が終わったらデプロイを無効化すると確実です。

スクリプトを直したときは、Apps Script で保存したうえで
「デプロイ > デプロイを管理 > 編集（鉛筆）> バージョン：新バージョン > デプロイ」を実行してください。
新しくデプロイし直すと URL が変わるので、その場合は `survey.js` の `CONFIG.endpoint` も更新します。

### 別のアカウントに作り直す場合

1. スプレッドシートを新規作成し、URL の `/d/` と `/edit` のあいだの ID を控える
2. https://script.google.com で「新しいプロジェクト」を作り、`gas/Code.gs` を貼り付け、
   先頭の `SPREADSHEET_ID` を 1 の ID に書き換えて保存
3. 「デプロイ > 新しいデプロイ」→ 種類「ウェブアプリ」→ 実行：自分／アクセス：全員
4. 出てきた `.../exec` を `survey.js` の `CONFIG.endpoint` に貼る

### QRコードを作る

公開URL `https://ngn-acu-kouhou.github.io/taishitsu-check/survey/` を QRコード化して、
受付テーブルや施術ベッドの脇に置いてください（A5サイズ程度に印刷し、ラミネートすると再利用できます）。

## 当日の運用

- 体験・施術が終わったタイミングで「最後に3分だけアンケートにご協力ください」と QR を案内する
- 送信後の完了ページに、鍼灸で相談できることの一覧が出ます。**その場で読み切らなくてよい**ことを一言添えると、持ち帰って読んでもらえます
- スマホを持っていない方・操作が難しい方向けに、**受付用のタブレットか、スタッフのスマホを1台**用意しておくと回収率が上がります
- 会場の電波が弱い場合でも、送信に失敗した回答は端末に一時保存され、電波の良い場所でページを開き直すと自動送信されます

## 集計の見方

スプレッドシートの「回答」シートに1行1名で溜まります。主な列：

| 列 | 内容 |
| --- | --- |
| `satisfaction` | 満足度（とても満足〜不満） |
| `menu` | 受けた内容（鍼灸体験 / 鍼灸施術） |
| `before_image` / `before_image_other` | 体験前の印象（複数選択）と自由記述 |
| `after_change` | 体験後、その印象がどう変わったか |
| `quiz_picked_count` | 18項目のうち「鍼灸で相談できそう」と思っていた数 ＝ **啓蒙前の認知度** |
| `quiz_missed` | 選ばれなかった項目 ＝ **特に知られていない適応。次の広報でここを重点的に出す** |
| `insurance_known` | 保険適用の認知度 |
| `where_known` | 相談先の認知度 |
| `useful` / `barriers` | 医療・介護職の方のみ表示される設問（連携の評価と障壁） |
| `want_info` | 広告8項目以外に「分かると行きやすい」情報（選択式） |
| `want_info_other` | 同上の自由記述 ＝ **受療の障壁を直接示す一次情報。最優先で読む列** |
| `intent` | 今後の意向（来院意向・資料ニーズ） |

`quiz_picked_count` の平均は、そのまま「開催前の認知度」の指標になります。
回を重ねて記録すると、広報活動の効果を年度報告に載せられます。

`want_info` / `want_info_other` は、広告に出せない情報のうち何が求められているかを示します。
広告そのものには載せられなくても、**体験会での配布物・問い合わせ時の説明・会のサイトでの発信**で補える項目が見つかります。

## 設問を変えたいとき

`survey.js` の上部にある `STEPS`（設問）と `QUIZ_ITEMS`（STEP 5 の選択肢 ＝ 完了ページの一覧）を編集するだけです。
HTML・CSS・Apps Script を触る必要はありません。新しい設問は、集計シートの右端に自動で列が増えます。
